# Connectify --- Open Source Contribution & Bounty Program

**Status:** Open for Contributions\
**Project:** Connectify\
**Currency:** US Dollars (USD)\
**Bounty Model:** Fixed rewards per accepted and verified contribution\
**Contributors:** Open to developers worldwide

Connectify is inviting developers, designers, security researchers, and
open-source enthusiasts to help build a polished, reliable, scalable,
and production-ready product.

Whether you're fixing a small UI issue, improving an API, redesigning a
page, identifying security vulnerabilities, or building an entirely new
feature, your contributions are welcome.

**Our goal is simple: Make Connectify an exceptional product through
community-driven development.**

We believe good contributions deserve recognition and fair compensation.

## 4. Security & Performance Bounties

Security and performance improvements are among our highest-priority
contributions.

We welcome responsible vulnerability reports and meaningful performance
optimizations.

### Security Opportunities

-   Broken access control.
-   Authentication vulnerabilities.
-   Authorization bypass.
-   Sensitive information exposure.
-   SQL injection.
-   Cross-site scripting (XSS).
-   Unsafe file uploads.
-   Missing rate limiting.
-   Insecure API endpoints.
-   Session-management vulnerabilities.

### Performance Opportunities

-   Slow API responses.
-   Inefficient database queries.
-   Memory leaks.
-   Excessive frontend rendering.
-   Large bundle sizes.
-   Unnecessary network requests.
-   Poor caching strategies.

### Rewards

  Severity / Impact          Reward
  ------------------- -------------
  Minor issue            \$21--\$32
  Moderate issue         \$32--\$65
  High-impact issue      \$65--\$86
  Critical issue        \$86--\$107

Rewards depend on severity, reproducibility, impact, and complexity.

**Responsible Disclosure:** Security vulnerabilities must be reported
privately to the maintainer. Do not access other users' accounts or
data, conduct destructive testing, or attack third-party services.

## 8. How to Claim a Bounty

Follow these steps:

**Step 1 --- Find an Issue**

Explore the repository and identify an existing issue or suggest a
meaningful improvement.

**Step 2 --- Discuss Your Idea**

Comment on the issue explaining: - What you want to fix or improve. -
Your proposed approach. - How you intend to test it.

**Step 3 --- Get Approval**

Wait for the maintainer to approve the work and confirm the reward.

**Step 4 --- Start Development**

Create a separate branch and implement the approved changes.

**Step 5 --- Submit a Pull Request**

Reference the approved issue and provide a clear explanation of your
changes.

**Step 6 --- Review**

The maintainer reviews your contribution and requests changes if
necessary.

**Step 7 --- Get Rewarded**

Once accepted, your approved bounty becomes eligible for payment.

Please do not begin substantial bounty work before receiving approval.

## 9. Pull Request Requirements

Every submission should include:

-   A descriptive PR title.
-   A reference to the approved issue.
-   A clear explanation of the changes.
-   Root cause and solution, where applicable.
-   Testing instructions.
-   Relevant screenshots for UI improvements.
-   Updated documentation when necessary.
-   No unrelated code changes.
-   No exposed API keys, passwords, tokens, or secrets.

AI-assisted development is welcome.

However, contributors are responsible for understanding, reviewing,
testing, and maintaining all submitted code.

Unreviewed AI-generated code will not qualify for a bounty.

------------------------------------------------------------------------

## 10. Review & Payment Policy

We aim to make the contribution process transparent and
contributor-friendly.

### Review Process

-   Every approved contribution receives a review.
-   Maintainers should aim to provide an initial response within 72
    hours.
-   Review feedback should be clear and actionable.
-   Contributors should have a reasonable opportunity to address
    requested changes.

### Payment Conditions

A bounty becomes payable when:

1.  The contribution matches the approved scope.
2.  The implementation passes verification.
3.  Required tests pass or accepted limitations are documented.
4.  The PR is merged or explicitly accepted.
5.  The contributor complies with repository rules.

### Payment Details

-   Currency: USD.
-   Payment method: Confirmed by the maintainer before work begins.
-   Payment timeline: Communicated before accepting the bounty.
-   Contributors are responsible for applicable taxes and reporting
    obligations.

Duplicate, previously reported, unapproved, or incomplete contributions
are not eligible.

------------------------------------------------------------------------

## 11. What Does Not Qualify?

The following contributions are generally not eligible:

-   Unapproved changes.
-   Duplicate bug reports.
-   Already-fixed issues.
-   Unrelated code refactoring.
-   Cosmetic changes without meaningful improvement.
-   Features outside Connectify's goals.
-   Changes that introduce regressions.
-   Unnecessary dependencies.
-   Spam pull requests.
-   Artificially splitting contributions to collect multiple rewards.
-   Vulnerability testing without authorization.

Maintainers reserve the right to reject submissions that do not meet the
agreed requirements.
